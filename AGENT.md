# AGENT.md

Guidance for AI coding agents (and people) working in this repository.

## What this repository is

`github-apiroute` publishes Python clients for GitHub's REST and GraphQL APIs. The clients are **generated** by [apiroute](https://github.com/dougyouch/apiroute):
- the REST client from GitHub's published OpenAPI description;
- the GraphQL client from GitHub's introspected schema plus the operations in `operations/graphql/`.

They're kept current by the weekly Build workflow, and released to PyPI as `github-apiroute`.

## Layout

| Path | What it is | Edit by hand? |
| --- | --- | --- |
| `apis.yaml` | Both APIs: spec URL, docs URL, module, client class, auth base class, and for GraphQL the endpoint, operations folder and scalar mappings | **yes**: this is the source of truth |
| `operations/graphql/` | The GraphQL operations (queries, mutations, shared fragments), one method each | **yes** |
| `specs/` | Committed copies of the REST description and GraphQL schema, written by `scripts/generate.py --fetch` | no (fetch them) |
| `scripts/generate.py` | Fetches specs (introspecting the GraphQL schema with `GITHUB_TOKEN`), runs `apiroute generate` per API, writes the README table | yes |
| `src/github_apiroute/auth.py` | `GitHubAuth` (token, API version header, retry safety), which both generated clients extend | **yes** |
| `src/github_apiroute/__init__.py` | Package docstring | yes |
| `src/github_apiroute/rest/`, `graphql/` | Generated clients (every file starts with `# Generated by apiroute`) | **never** |
| `tests/` | Config checks, auth, GraphQL operations | yes |
| `.github/workflows/` | `ci.yml`, `build.yml` (regenerate and commit), `release.yml` (release-please, auto-merge and PyPI) | yes |
| `.agent/skills/apiroute-client.md` | Skill for creating and maintaining repos like this one | yes |

## Rules

- **Never edit generated code.** CI regenerates from `specs/` and fails on any difference. To change generated output:
  - Edit `apis.yaml`, `operations/graphql/` or `auth.py` and regenerate.
  - If the generator itself is wrong, fix apiroute; the Build workflow picks up its next release.
- **Regenerate after any change** to `apis.yaml`, the operations or the generate script: `uv run python scripts/generate.py`. Add `--fetch` to download the latest specs first (it needs `GITHUB_TOKEN`, e.g. `GITHUB_TOKEN="$(gh auth token)"`). Commit the specs, operations and generated code together.
- **Never write a token to a file or print it.** Pass it through the environment only.
- **Credentials belong in `auth.py`.** Every generated root client extends `GitHubAuth`; spec-declared security schemes aren't generated.
- **Use conventional commits.** release-please derives versions from them:
  - `feat:` is a minor release
  - `fix:` is a patch
  - `chore:`, `docs:`, `test:` and `ci:` produce no release
- **Before committing:** `uv run ruff check .`, `uv run ruff format --check .` and `uv run pytest`. After regenerating, also run the live tests: `GITHUB_TOKEN="$(gh auth token)" uv run pytest tests/live`.
- **Live tests only read.** Never add a test that creates, changes, stars or deletes anything on GitHub; mutations are tested with `MockTransport`.
- **`nullable_fields: true` stays on the REST API.** GitHub's REST description declares some fields never null that the API sends as null; the GraphQL schema is accurate and doesn't need it.

## Common tasks

- **Add a GraphQL operation:**
  1. Write it in a `.graphql` file under `operations/graphql/`. The folder is the section (`repos/` → `gh.repos`); top-level files go on the root client. Reuse the fragments in `fragments.graphql`.
  2. For a connection, select `pageInfo { hasNextPage endCursor }`, take an `$after: String` variable, and mark the field `@paginate`.
  3. Run `scripts/generate.py --only graphql`. The generator validates the operation against `specs/graphql.graphql`.
  4. Add a test in `tests/test_graphql.py` using `MockTransport`. Don't run mutations against the real API.
- **A spec change broke generation:** the Build workflow fails before committing anything. Reproduce with `GITHUB_TOKEN="$(gh auth token)" scripts/generate.py --fetch`, then fix the operation (a field GitHub removed or renamed), apiroute or `auth.py`. Patching `specs/` by hand would be overwritten by the next fetch.
- **Release:** nothing to do. `release.yml` tests the release PR that release-please keeps open, merges it, tags it and publishes to PyPI (trusted publishing, the `pypi` environment), whenever releasable commits land, including Build's. Merging the release PR by hand still works. Running Release manually retries publishing the current version.

## Skill

`.agent/skills/apiroute-client.md` describes how to create, set up and maintain a client repository like this one for any API with OpenAPI/Swagger specs, WSDLs or GraphQL schemas. Read it before restructuring this repo or creating a sibling.
